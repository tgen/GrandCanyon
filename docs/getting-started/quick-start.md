# Quick Start Guide

{: .note }
> Fastest path from raw data to results. For the full configuration schema, see the [Configuration Guide](../configuration/). For detailed command options, see the [Execution Guide](../execution-guide/).

## Overview

GrandCanyon supports processing samples against any reference, we default to GRCh38 using Ensembl v113 gene models. It supports:

- **DNA** (whole-genome and exome): alignment (BWA-MEM2 or MiniBWA), QC, constitutional/somatic/tumor-only variant calling, structural variants, copy number, and VEP annotation.
- **RNA**: STAR alignment and quantification, Salmon quantification, and STAR-Fusion fusion calling.

## Built-in References

Reference definitions live in `constants.grandcanyon` of `pipeline.yaml`:

| Reference | Build | Notes |
|-----------|-------|-------|
| `grch38` | GRCh38 with TGen decoy/ALT/HLA additions, Ensembl v113 gene models | Default when no `reference` is set |
| `chm13` | T2T-CHM13 v2 | T2T reference |
| `canfam4` | Canis familiaris CanFam4 | Dog |
| `grcm39` | Mus musculus GRCm39 | Mouse |

To select one, set it at the top level of the configuration JSON:

```json
{
  "project": "GIAB_NA12878",
  "reference": "chm13",
  ...
}
```

For a **custom reference**, supply the equivalent `constants.grandcanyon` object in your
configuration JSON with your resource paths (reference FASTA, aligner index, interval lists,
VEP cache, etc.). Any task that requires a resource not supplied for the custom reference must
stay disabled through its `tasks` toggle.

> [!NOTE]
> The exact set of required resources per tool is defined in `constants.grandcanyon[<reference>].tool_resources`
> in `pipeline.yaml`; use it as a template when building custom reference constants. This section is a
> draft pending team review.

## Prerequisites

- **JetStream CLI** installed (`jetstream init` and `jetstream pipelines`)
- **Paired-end FASTQ** input
- A **configuration JSON** describing your samples
- A **container runtime** (Docker or Singularity) available to the execution backend

## Step 1: Create the configuration

GrandCanyon reads a flat `dataFiles` array with one entry per FASTQ file. Each read group is identified by `rgid`, and R1/R2 pairs are identified by `fastqCode`.

Minimal whole-genome constitutional example:

```json
{
  "project": "GIAB_NA12878",
  "study": "GIAB",
  "pipeline": "grandcanyon",
  "dataFiles": [
    {
      "sampleMergeKey": "GIAB_NA12878_1_CL_Whole_C1_TPFWG",
      "sampleName": "GIAB_NA12878_1_CL_Whole_C1_TPFWG_K18088",
      "glType": "genome",
      "glPrep": "genome",
      "subGroup": "constitutional",
      "fastqCode": "R1",
      "fastqPath": "/path/to/sample_R1.fastq.gz",
      "rgid": "RG001",
      "rgsm": "GIAB_NA12878_1_CL_Whole_C1",
      "rgpl": "ILLUMINA",
      "rglb": "K18088",
      "rgpu": "FLOWCELL_LANE"
    },
    {
      "sampleMergeKey": "GIAB_NA12878_1_CL_Whole_C1_TPFWG",
      "sampleName": "GIAB_NA12878_1_CL_Whole_C1_TPFWG_K18088",
      "glType": "genome",
      "glPrep": "genome",
      "subGroup": "constitutional",
      "fastqCode": "R2",
      "fastqPath": "/path/to/sample_R2.fastq.gz",
      "rgid": "RG001",
      "rgsm": "GIAB_NA12878_1_CL_Whole_C1",
      "rgpl": "ILLUMINA",
      "rglb": "K18088",
      "rgpu": "FLOWCELL_LANE"
    }
  ]
}
```

For most internal TGen users, this file is generated by the TGen LIMS. See the [Configuration Guide](../configuration/) for every field.

## Step 2: Initialize the project

```bash
jetstream init GIAB -C GIAB_NA12878_config.json
```

This creates a JetStream project directory named `GIAB` and loads your configuration into it.

## Step 3: Run the pipeline

```bash
jetstream pipelines grandcanyon -p GIAB
```

This renders the GrandCanyon template, builds the workflow, and starts execution. To render/build without running, use `-r` or `-b`:

```bash
jetstream pipelines grandcanyon -p GIAB -r   # render only
jetstream pipelines grandcanyon -p GIAB -b   # render + build, do not run
```

## Step 4: Review outputs

Results are written under the project directory in `<glType>/<analysis>/<tool>/<sample>/` folders, for example `genome/alignment/bwa/...` and `genome/somatic_variant_calls/mutect2/...`. See the [Output Structure](../../outputs/) documentation for the full layout.
